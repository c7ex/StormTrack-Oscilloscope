# StormTrack

**Read this in other languages:** [English](README.md)

**StormTrack** — C++ WinApi библиотека для отображения временных рядов в реальном времени на Windows с использованием GDI. Основное назначение: ускорение разработки R&D проектов с визуализацией в среде Visual Studio. Библиотека представляет собой программный осциллограф: позволяет строить статические и потоковые данные. Окно отрисовки выполняется в отдельном потоке, оставляя консоль отзывчивой. Хорошая производительность для миллиона точек.

![Пример интерфейса](screen/v1.6.0.gif) 

## Основные возможности

- **Несколько графиков** в одном окне.
- **Потоковое обновление** — данные непрерывно загружаются в реальном времени.
- **Статические данные** — наборы данных среднего размера (1M+).
- **Встроенная поддержка комплексных данных** — визуализация I/Q сигналов с отдельными трейсами для действительной и мнимой частей через `std::complex<double>`.
- **Масштабирование** колёсиком мыши (по XY или только по X с зажатым Shift); масштабирование относительно положения курсора.
- **Панорамирование** (перетаскивание) левой кнопкой мыши в области графика.
- **Автоподгонка по X** — клавиша `A` включает/выключает автоматическую подстройку видимой области под все активные трейсы.
- **Автоподгонка по Y** — клавиша `S` включает/выключает автоматическое масштабирование оси Y для всех видимых данных.
- **Автоотслеживание** — нажмите `Q`, чтобы область просмотра автоматически следовала за поступающими данными (окно «едет» за последними точками).
- **Отображение FPS** — клавиша `F` включает/выключает отображение производительности рендеринга.
- **Легенда** — список трейсов с возможностью скрытия/отображения (клик по цветному квадрату).
- **Отслеживание данных** — при наведении курсора на график подсвечивается ближайшая точка и отображаются её координаты.
- **Адаптивная сетка** с числовыми подписями.
- **Изменяемый размер области графика** — границы поля можно перетаскивать.
- **Многопоточность** — окно работает в отдельном потоке, не блокируя основной поток консольного приложения.
- **Умный рендеринг с устранением артефактов алиасинга** — динамическое сжатие данных и выравнивание по фазе обеспечивают стабильное панорамирование без мерцания.
- **Два режима стриминга** — полная замена кадра (`FrameView` с перемещением данных) или непрерывное добавление (`RealtimeView` с копированием), дающие полный контроль над владением данными.
- **Отсутствие внешних зависимостей** — чистый Win32/GDI, никаких Qt, boost или дополнительных DLL. Просто подключите заголовочные файлы и статическую библиотеку.
- **Настраиваемый внешний вид интерфейса** — цвета фона, видимость счётчика FPS и другие визуальные параметры доступны в одном заголовочном файле `ConfigUI.hpp` (требуется сборка проекта).

## Производительность

Все измерения ниже проводились при ограничении времени кадра в **16 мс** (≈60 FPS),
что соответствует внутреннему интервалу таймера рендеринга.

> **Важно:** приведённые ниже значения описывают случай, когда **отрисовываются все точки данных**.
> На практике FPS напрямую зависит от **видимой части** отображаемых данных:
> библиотека отрисовывает только те точки, которые попадают в текущую область просмотра,
> поэтому увеличение масштаба (уменьшение видимого диапазона) повышает производительность,
> а уменьшение масштаба (отображение всего набора данных) — самый тяжёлый случай.
> Таким образом, значения ниже представляют собой **наихудший сценарий** — полностью
> видимый набор данных при включённом автомасштабировании.

> **Замечание о термине «FPS»:** здесь часто путают две разные метрики.
> - **FPS рендеринга (внутренний)** — сколько полностью отрисованных кадров библиотека
>   способна выдать в секунду, *если бы её не ограничивал таймер*. Эта величина показывает
>   реальный вычислительный запас рендерера и именно она измеряется в таблице ниже.
> - **FPS пользователя (на экране)** — сколько кадров пользователь фактически видит в окне.
>   Это значение ограничено внутренним таймером рендеринга на уровне **≈60 FPS**
>   (интервал 16 мс), поэтому оно никогда не превысит этот предел, как бы быстро
>   ни работал рендерер.
>
> Иными словами: если *FPS рендеринга* **выше 60**, пользователь видит плавные
> **60 FPS**. Если *FPS рендеринга* падает **ниже 60** (например, ~34 или ~19 в таблице),
> пользователь видит именно это меньшее значение — таймер просто не успевает,
> и каждый кадр вычисляется дольше 16 мс.

**Тестовое железо:** Intel Core i5-7300HQ (ноутбучный CPU, 2017–2018).

| Точек данных | Трейсов | FPS рендеринга | Фактический FPS              |
|--------------|---------|----------------|------------------------------|
| 100 тыс.     | 10      | ~87            | 60 (ограничен)               |
| 500 тыс.     | 10      | ~50            | ~50                          |
| 1 млн        | 10      | ~34            | ~34                          |
| 1 млн        | 1       | ~140           | 60 (ограничен)               |
| 5 млн        | 1       | ~65            | 60 (ограничен)               |
| 10 млн       | 1       | ~37            | ~37                          |
| 20 млн       | 1       | ~19            | ~19                          |

## Сборка

### Способ 1 — готовый SDK (рекомендуется)
1. Получите SDK. Если в [Releases](https://github.com/c7ex/StormTrack-Oscilloscope/releases) доступен готовый SDK (.zip), скачайте его и распакуйте.
   Иначе откройте решение `vs\StormTrack.sln` и соберите проект в конфигурации Release —
   в папке `bin\x64\Release` появятся `StormTrack.lib` и `StormTrack.hpp`.
2. Скопируйте в свой проект файлы `StormTrack.lib` и `StormTrack.hpp`.
3. В настройках проекта Visual Studio:
   - **C/C++ → General → Additional Include Directories** – укажите папку, где лежит `StormTrack.hpp`.
   - **Linker → Input → Additional Dependencies** – добавьте `StormTrack.lib`.
   - **Linker → General → Additional Library Directories** – укажите папку, где лежит `StormTrack.lib`.
4. Подключите заголовок: `#include "StormTrack.hpp"`.

**Примечание:** проект `Demo` имеет пример подключения.

### Способ 2 — CMake (Windows)
Альтернатива решению Visual Studio. Требуется CMake 3.16+ и Visual Studio 2017+.
1. Запустите `cmake\build.cmd` — версия Visual Studio определится автоматически.
2. Результат сборки появится в `bin\x64\Release\`:
   - `StormTrack.lib`
   - `StormTrack.hpp`
   - `StormTrackDemo.exe`
3. Промежуточные файлы сборки (solution, проекты VS) лежат в `cmake\build\`.

Для очистки артефактов запустите `cmake\clean.cmd`.

### Способ 3 — добавление исходных файлов в свой проект
1. Создайте консольное приложение в Visual Studio.
2. Добавьте в проект все папки с исходниками `GraphCore\`, `GraphModules\`, `RaiiWinApi\`, `StormTrack\`. Требуется указать все пути до `.hpp` и `.cpp`.
3. Если хотите добавить в проект иконку, требуется добавить папку `res` (`ico2hpp.vbs` + `stormtrack.ico`) и команду пребилда иконки. Пример команды: `cscript //nologo "$(ProjectDir)..\..\res\ico2hpp.vbs" "$(ProjectDir)..\..\res\stormtrack.ico" "$(ProjectDir)..\..\src\StormTrack"` - главное, чтобы сгенерированный `StormTrackIconData.hpp` был виден в вашем проекте. Как альтернативный вариант, взять файл `StormTrackIconData.hpp` из собранного SDK.
4. Соберите в Debug/Release.

**Примечание:** если возникнет ошибка C1010, отключите предкомпилированные заголовки в настройках проекта.

> **Совместимость версий компилятора**  
>  
> Готовый `StormTrack.lib` в SDK собран с **Platform Toolset v143** (Visual Studio 2022).  
> Если ваш проект использует более новую версию инструментов (например, **v145** из Visual Studio 2026 Preview), при линковке могут возникнуть ошибки (`LNK2038` или похожие) из-за несовместимости ABI.  
>  
> **Как это исправить:**  
> - **Вариант 1 (рекомендуемый):** Переключите `Platform Toolset` вашего проекта на **v143** (или любую версию от v140 до v143). Это обеспечит бинарную совместимость без пересборки SDK.  
> - **Вариант 2:** Пересоберите `StormTrack.lib` самостоятельно под нужный вам toolset. Скачайте исходный код, откройте решение, измените `Platform Toolset` проекта `StormTrack` на вашу версию (например, v145) и выполните сборку в конфигурации Debug/Release.

Ваше консольное приложение будет готово использовать визуализацию.

Также собранный SDK может содержать готовые сборки для разных тулсетов (v143, v145).

## Быстрый старт

### Статический график

```cpp
#include "StormTrack.hpp"

std::vector<double> data = // ...

HINSTANCE hInstance = GetModuleHandle(nullptr);
StormTrack window(hInstance, L"[Пример] статические данные");
window.JustView(data, L"Данные", RGB(255, 120, 120));
window.Show();

// ...

window.Close();
window.WaitForClose();
```

### Потоковая замена кадров

Полная замена данных каждый кадр. Вектор перемещается — после вызова становится пустым.

```cpp
#include "StormTrack.hpp"

HINSTANCE hInstance = GetModuleHandle(nullptr);
StormTrack window(hInstance, L"[Пример] потоковая замена");
window.Show();

size_t traceId = window.AddTrace(L"Данные", RGB(255, 120, 120));

for (;;) {
    std::vector<double> data = // ...
    window.FrameView(data, traceId); // data перемещается, становится пустым
}

window.Close();
window.WaitForClose();
```

### Накопление в реальном времени

Добавляет данные в конец трейса. Исходный вектор сохраняется.

```cpp
#include "StormTrack.hpp"

HINSTANCE hInstance = GetModuleHandle(nullptr);
StormTrack window(hInstance, L"[Пример] накопление данных");
window.Show();

size_t traceId = window.AddTrace(L"Данные", RGB(255, 120, 120));

for (;;) {
    std::vector<double> chunk = // ...
    window.RealtimeView(chunk, traceId); // chunk копируется, остаётся нетронутым
}

window.Close();
window.WaitForClose();
```

### Комплексные данные (I/Q)

Библиотека поддерживает `std::complex<double>` «из коробки». Действительная и мнимая части отображаются как отдельные трейсы с помощью тех же методов `FrameView` и `RealtimeView`.

```cpp
#include "StormTrack.hpp"

HINSTANCE hInstance = GetModuleHandle(nullptr);

// Инициализация окна
StormTrack window(hInstance, L"[Пример] I/Q стриминг");

// Добавляем два трейса: I (действительная) и Q (мнимая)
size_t traceI = window.AddTrace(L"I (действ.)", RGB(255, 100, 100));
size_t traceQ = window.AddTrace(L"Q (мним.)", RGB(100, 100, 255));

window.Show();

// Замена кадра (полное обновление)
for (;;) {
    std::vector<std::complex<double>> iq_data;
    // ... генерация или получение I/Q данных ...

    // Обновляем оба трейса одновременно
    window.FrameView(iq_data, traceI, traceQ);
}

window.Close();
window.WaitForClose();
```

### Unique-API

Высокоуровневое API, где не нужно хранить `trace_index` — трейс адресуется по уникальному имени. Если трейса с таким именем ещё нет, он будет создан; если есть — данные добавятся к нему. Рекомендуется использовать именно это API.

```cpp
#include <complex>
#include <vector>
#include "StormTrack.hpp"

int main() {
    HINSTANCE hInstance = GetModuleHandle(nullptr);
    StormTrack window(hInstance, L"[Пример] API по именам");
    window.Show();

    // Создать трейс (или обновить параметры существующего)
    window.UniqueTrace(L"Data 1", RGB(255, 0, 0));

    // Стриминг: создание трейса, если он не был создан, и замена вектора данных
    std::vector<double> data = /*...*/;
    window.UniqueStream(data, L"Data 1");

    // Накопление: создание трейса, если он не был создан, и добавление вектора данных в конец
    std::vector<double> chunk = /*...*/;
    window.UniquePushBack(chunk, L"Data 2", RGB(100, 100, 200));

    // Накопление: создание трейса, если он не был создан, и добавление одной точки данных в конец
    window.UniquePushBack(3.14, L"Data 2");

    // Комплексные данные: автоматически создаст два трейса "Signal-Re" и "Signal-Im", в данном случае пример стриминга
    std::vector<std::complex<double>> iq_data = /*...*/;
    window.UniqueStream(iq_data, L"Signal", RGB(0, 255, 0), RGB(0, 0, 255));

    // В данном примере не нужен — программа не закрывает окно принудительно.
    // window.Close();

    // Ждём, пока пользователь закроет окно
    window.WaitForClose();

    return 0;
}
```

## Описание API

| Метод | Назначение | Владение данными |
|-------|-----------|-----------------|
| `JustView(data, name, color, step, offset)` | Загрузить статический график | Копирует |
| `AddTrace(name, color, step, offset)` | Создать трейс, возвращает ID | — |
| `FrameView(data, traceId)` | Полная замена кадра | Перемещает |
| `RealtimeView(data, traceId)` | Добавить данные в конец трейса (вектор) | Копирует |
| `RealtimeView(value, traceId)` | Добавить одно значение в конец трейса | Копирует |
| `JustView(complex_data, caption_re, caption_im, color_re, color_im, step, offset)` | Загрузка статического графика для комплексных данных (отдельные трейсы для Re и Im) | Копирует |
| `FrameView(complex_data, trace_index_re, trace_index_im)` | Полная замена кадра для комплексных данных (обновляет Re и Im одновременно) | Копирует |
| `RealtimeView(complex_data, trace_index_re, trace_index_im)` | Добавление блока комплексных данных в конец трейсов Re и Im | Копирует |
| `RealtimeView(complex_value, trace_index_re, trace_index_im)` | Добавление одного комплексного значения в конец трейсов Re и Im | Копирует |
| `Show()` | Открыть окно в фоновом потоке | — |
| `Close()` | Отправить сигнал закрытия окну | — |
| `WaitForClose()` | Дождаться завершения потока окна | — |
| `IsActive()` | Проверить, открыто ли окно | — |
| `UniqueTrace(caption, color, step, offset)` | Создать трейс по имени или обновить параметры существующего | — |
| `UniqueStream(data, caption[, color, step, offset])` | Стриминг `std::vector<double>` по имени трейса | Перемещает |
| `UniqueStream(complex_data, caption[, color_re, color_im, ...])` | Стриминг `std::vector<std::complex<double>>` — создаёт трейсы `caption-Re` и `caption-Im` | Копирует |
| `UniquePushBack(data, caption[, color, step, offset])` | Добавить вектор `std::vector<double>` в конец трейса по имени | Копирует |
| `UniquePushBack(point, caption[, color, ...])` | Добавить одно значение `double` в конец трейса по имени | Копирует |
| `UniquePushBack(complex_data, caption[, color_re, color_im, ...])` | Добавить блок комплексных данных в конец трейсов `-Re` и `-Im` | Копирует |
| `UniquePushBack(complex_point, caption[, color_re, color_im, ...])` | Добавить одно комплексное значение в конец трейсов `-Re` и `-Im` | Копирует |

## Управление

| Действие | Управление |
|----------|------------|
| Масштабирование | Колёсико мыши. Обычно — одновременно по X и Y. С зажатым `Shift` — только по X. С зажатым `Ctrl` — быстрый зум. Масштаб меняется относительно положения курсора. |
| Перемещение (панорамирование) | Зажать левую кнопку мыши на области графика и тянуть. |
| Автомасштаб по X | Клавиша `A` (работает как переключатель). Когда включён, видимая область автоматически подстраивается под весь диапазон активных трейсов по оси X. |
| Автомасштаб по Y | Клавиша `S` (работает как переключатель). Когда включён, ось Y автоматически масштабируется под все видимые данные. |
| Включение/выключение режима автодорожки (окно следует за новыми данными) | Клавиша `Q` |
| Отображение FPS | Клавиша `F` (работает как переключатель). Когда включён, отображает количество отрисованных кадров в секунду. |
| Легенда (скрыть/показать трейс) | Клик по цветному квадратику в правой части окна. Трейс временно скрывается или снова отображается. |
| Отслеживание координат | Навести курсор на график — ближайшая точка данных подсвечивается, а рядом с указателем появляется подсказка с её координатами. |
| Изменение размера области графика | Подвести курсор к границе тёмной рамки (появится двусторонняя стрелка) и перетащить границу. Скрывает или разворачивает панель с легендой. |
